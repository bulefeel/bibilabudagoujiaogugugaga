# 批量删除建档：实现与验收（2026-09-28）

## 范围

本轮只增加通用批量建档重置，不改变亚马逊页面识别、登录、提现状态机、队列规则。
没有按此前十家店铺的 ID 或名称写条件。十店实测不是所有店铺都兼容的证明；该问题仍需按页面状态类别归纳，而非按店铺逐个特判。

## 操作

店铺账册 → 筛选亚马逊店铺 → 勾选卡片“选择店铺”（或“选择当前可见亚马逊店铺”）→ 批量删除建档（数量）→ 核对逐店名单 → 确认。

- 没有显式勾选时按钮禁用，不把零选择解释为全选。
- 隐藏、未选和其他平台店铺不参与。
- 可用“清空勾选”重新选择。
- 弹窗冻结店铺 ID 和配置版本；取消不发起请求。
- 成功后清除涉及目标店铺的暂停本地建档队列，并明确提示需重新预览；失败保留队列。

## 删除的含义

沿用原单店重置契约：清空卖家 ID、撤销身份确认、关闭店铺任务开关、停用该店排期及下次运行时间，增加建档配置版本。

保留店铺与紫鸟环境、CA/UK/AU/DE 站点及勾选、历史核验、历史运行、截图和全部资金防重复记录。历史核验保留，但不再冒充当前配置的已通过结果；可重新建档。排期仅停用，不删除。

## 接口与事务

`POST /api/stores/setup/reset-batch`

请求只接受 `stores: [{store_id, expected_setup_revision}]`，1–500 家，不接受重复 ID、额外字段、字符串/布尔 ID 或负版本。

- 先检查进程内活动建档，再以 SQLite BEGIN IMMEDIATE 保护持久状态预检和整批变更。
- 所有目标预检通过才写入；任何店铺被活动建档、未结束任务、活动队列、未确认窗口清理或配置变化阻断时，409 返回逐店原因，整批零改动。
- 全部更新一次事务提交；排期刷新只调用一次。
- 同一个旧确认清单重试会被配置版本检查阻断；并发请求最多一个成功。
- 排期刷新/浏览器缓存失败发生在服务器提交之后时，仍显示已删除，不引导重复提交。
- 未引入新表、迁移或依赖，不改资金记录或资金判断。
