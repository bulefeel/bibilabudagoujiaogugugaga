# 0.8.0 发布说明

源码与 Windows EXE 安装包由同一 Git 提交构建。以当前本地已调试代码为基线，本次发布不另行调整业务提交规则。

## 相对 0.7.1 的更新

- 新增「库存待批准商品合规处理」，支持 IT、FR、ES、PL、DE，复用现有店铺、批量排期、串行队列及历史页面。
- 同一自动化分别处理安全证明、负责人和制造商要求。支持 dry_run / auto，默认只读；旧配置不自动增加处理项目。
- 商城依据页头实际选择确认，域名与商城分别校验；适配多级商城菜单及切换后的加载状态。
- 完整处理分页内懒加载，保存每站候选快照，从末页末行向前执行；单项失败按既有规则有限重试并记录。
- 支持同商品多个违规入口、已有关联跳过和第一条可操作且未失效记录选择，不创建新联系人。
- 识别负责人及制造商的两种简繁体审核中回执，包括“您提交的内容正在审核中。”；确认后继续其他要求与商品，不重复送出。
- 先处理当前待批准列表，不前置搜索已离开列表的历史商品。历史保留；本轮提交不明时保留进度，未决回读不冒充确认。
- 完善已识别公告关闭、侧栏加载、403 状态分类、取消收尾、断线诊断及多站点完成结果。
- 飞书及运行详情分开统计商品和要求，展示已提交、审核中、已有关联、跳过、失败、尚未检查及结果不明。
- 批量建档扩展至 DE、IT、FR、ES、PL，按明确选择只读核对商城和库存访问；身份、站点及付款能力分别保存。
- 库存等待及重试参数随安装包分发，避免安装版缺少本地新增策略文件。

## 保留与兼容

- 原「监管合规性」GPSR、Feedback、提现和本机管理入口继续保留。
- 提现站点范围仍限 CA、UK、AU；本次发布不另行修改其资金提交语义。
- 账号及站点选择沿用公共登录模块，仅在实际出现相应页面时处理。
- 后台仍只监听 127.0.0.1；凭据保留在原存储位置，不打入安装包。
- 旧的 0.7.1 发布与附件保留，不覆盖。

## 安装与升级

- 使用 `ZiniaoAutomation-Setup-0.8.0.exe`，可选择 D 盘；Python、数据库、日志和证据随安装目录保存。
- 从 0.7.1 升级至数据库 0017，依次运行 0013–0017。迁移前使用 SQLite Backup API 一致性备份，保留既有店铺、排期及历史。
- 升级标记阻止因本次安装停机而补跑排期；已有正常排期仍按原设置运行。
- 降级应配套使用升级前数据库备份，不直接让旧版程序读取新数据库结构。
- 安装包只包含发布白名单源码、配置和工具链，不包含开发机数据库、凭据、录屏、原始页面或诊断记录。

## 验证边界

- 本地本轮回执修复回归：1927 项非浏览器测试通过、1 项跳过；285 项库存离线页面测试通过。
- 新增 34 项回执用例，覆盖新旧简繁体、负责人/制造商、错误商品及要求、非编辑态、取消和重启只读回读；SQLite 与真实页面适配器离线验证连续处理多个商品。
- 发布构建另在独立环境中从暂存源码运行完整测试；最终结果、提交号及 SHA256 写入 Release 和发布清单。
- 离线 DOM 测试使用断网 about:blank 样本；本次发布不执行真实商品提交、提现或新增店铺测试。
- 新安装和升级后的真实业务效果由使用方验收，不将构建通过表述为所有店铺均已实测。
