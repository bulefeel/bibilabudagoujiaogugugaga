# 0.9.0：提现扩站与批量建档修复

## 本次同步范围

- 提现支持新增美国 USD、德国 EUR，配套更新登录域名、站点选择、工作流元数据、排期及建档校验。旧排期及已排队配置不自动增加站点，资金提交、防重复、审批及回读逻辑继续沿用。
- 法国库存兼容“修正限制刊登問題”等入口；单件入口错误单独记录，继续后续商品和站点。
- 已建档店铺可批量补充新站点，不必删除原建档；保留未选站点及已有核验结果。
- 基础身份和站点验证、付款能力、库存能力分别保存。德国优先核验付款首页，库存筛选未就绪不抹掉基础身份。
- 批量建档持续跟踪服务端探针，不再受前端六分钟截止限制；读取超时有限重试，刷新后恢复原进度，并防止旧响应覆盖当前状态。
- 显示待释放环境的检查和释放入口，仅在确认环境已停止后解除阻挡；保留失败原因和业务记录，不自动重跑。
- 补站点时可从配置兼容的已通过站点实时复核身份。单站导航超时继续其他站点，单家启动失败继续其他店铺。
- 紫鸟启动最多四次，默认重试间隔为 3/6/9 秒，不重启整个客户端。设备未绑定等前置错误提供对应诊断。

## 数据与升级

- 数据库由 `0017` 升至 `0019`：`0018` 扩展提现站点，`0019` 保存库存能力。
- 历史建档的库存能力初始化为 `NOT_CHECKED`，不会凭旧成功状态宣称库存页面已核验。
- 安装前使用 SQLite Backup API 备份；回退旧程序时使用对应升级前数据库备份。
- Python、依赖版本及构建工具链保持锁定。源码、EXE、SHA256 与发布清单关联到同一 Git 提交。
- 不包含本地数据库、凭据、日志、截图、录屏及临时诊断文件；保留 0.8.0 发布资产。

## 验证范围

发布门槛为安装包暂存源码的完整测试、断网页面样本、前端语法与交互测试，以及真实数据库副本的迁移和数据保全核对。最终结果记录在 GitHub Release 和本地发布备份中。

本次发布不启动真实店铺任务，不进行真实资金、商品提交或飞书消息测试。美国、德国真实资金验收尚未完成；紫鸟网络启动错误的底层网络原因尚未确认，有限重试与诊断改进不等同于消除网络故障。
