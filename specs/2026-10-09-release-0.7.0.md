# 0.7.0 发布说明

0.7.0 将本地已调试的业务代码、店铺账册和建档修复统一到源码与安装包。

## 相对 0.6.3

- 新增德国站 GPSR 安全证明流程，支持 dry_run / auto。
- 同步提现、Feedback、GPSR 的账号/站点选择和登录落点处理。
- 提现提交后按本地派发事实结束处理，不再自动联网回读；“已提交”不代表平台确认或到账。
- 同步审核计划绑定、验证后续跑、跨日防重复、队列异常恢复与飞书通知修复。
- 移除本地后台管理员创建和登录页面，保留本机访问、来源和 CSRF 校验；紫鸟及亚马逊登录不受影响。
- 店铺账册按平台、名称、配置及任务开关筛选；批量建档限定在选定的亚马逊店铺范围。
- 完整紫鸟同步可删除已失去权限的店铺及排期，保留运行、截图及资金历史；列表不完整时阻断删除。
- 建档分离身份、站点访问及付款页面能力，逐站持久化核验结果，并支持补齐配置、重试未通过站点、复核所选店铺。
- 新增批量删除建档，保留店铺、站点选择和历史，停用相关排期。
- 建档 OTP 自动填充默认最多等待 15 秒；超时结束该站尝试，登录已成功则继续识别业务页。
- 修复身份已保存但卡片仍显示未绑定；身份和站点失败分别显示，重置后不会被旧历史恢复。

## 安装与升级

选择安装目录后，Python 环境、数据库、日志和证据随目录保存，可选择 D 盘。
从 0.6.3 升级时执行 0010–0012 迁移；迁移前由 SQLite Backup API 创建一致性备份。
新安装不需要创建管理员账号，直接在系统诊断页配置紫鸟和飞书。
安装包不包含开发机的数据库、凭据、店铺、截图或运行日志。
只读建档支持 CA/UK/AU；已有 DE 配置保留，GPSR 使用自己的德国站流程。

本版保留当前本地业务逻辑，不因发布再次调整资金规则。
提现、建档及 GPSR 使用固定流程；Feedback 判定可能调用配置的模型服务，不能把整个项目描述为完全不使用 AI。

## 验证范围

发布构建会从安装包暂存源码运行完整测试，并生成版本、Git 提交号及 SHA256 清单。
真实店铺历史验证与离线测试分别记录在 specs 中；构建成功不等于对所有店铺重新实测。
