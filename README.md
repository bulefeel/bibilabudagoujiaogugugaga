# 紫鸟多店铺本地自动化管理器 V1

本项目在 Windows 当前桌面会话中运行，管理后台仅监听
`http://127.0.0.1:8765`。SQLite、日志、截图、虚拟环境和缓存都放在安装目录下，
提现、建档和 GPSR 使用固定流程；Feedback 判定可能调用配置的模型服务。

当前版本 **0.9.1**，源码与 EXE 安装包使用同一提交构建，更新内容见 [发布说明](https://github.com/bulefeel/bibilabudagoujiaogugugaga/releases/tag/v0.9.1)。

0.9.1 修复建档“无窗口却待释放”的阻塞：新建档前自动检查旧核验的资源状态，必要时请求紫鸟停止对应的空闲店铺环境；批量运行中确认释放后继续剩余店铺。原失败结果、建档及业务记录保留。未取得停止确认或仍有活动业务时显示具体恢复目标和操作入口。详情见 [补丁说明](specs/2026-10-26-release-0.9.1.md)。

新增「库存待批准商品合规处理」流程，支持意大利、法国、西班牙、波兰及德国。
通过页头商城菜单切站，完整扫描分页和懒加载商品，分别处理安全证明、负责人信息及制造商信息。
`dry_run` 只检查，不勾选、不保存；`auto` 按所选处理项目逐项提交并核对「已提交、审核中」回执。
它与原「监管合规性」GPSR 流程分别保留，不使用提现审批或资金锁；旧排期不自动扩大处理范围。
先处理所选站点当前待批准商品，不前置搜索已经离开列表的历史商品；历史记录保留。
本轮提交结果不明确时保留进度，不把勾选或点击当作成功。
运行详情及飞书分开显示商品数、要求数、提交确认、跳过、失败和待处理结果。
等待与有限重试参数位于 `inventory-gpsr-policy.toml`，升级与验证说明见
[0.9.0 版本说明](specs/2026-10-26-release-0.9.0.md)。

批量建档支持 CA、UK、AU、US、DE、IT、FR、ES、PL；CA、UK、AU、US、DE 优先核验付款首页，
IT、FR、ES、PL 核验实际商城及库存访问。建档不提交业务操作，基础身份、站点、付款与库存能力分别记录。
提现流程支持 CA/CAD、UK/GBP、AU/AUD、US/USD、DE/EUR；新站点需在店铺建档和任务中明确选择，旧排期及已排队任务范围不变。德国库存建档不代表付款已核验，提现任务仍实时核对付款条件。

## 1. 安装（给非技术同事看的版本）

1. 双击 `ZiniaoAutomation-Setup-x.y.z.exe`。

2. **会出现一个蓝色窗口「Windows 已保护你的电脑」——这是正常的。**
   这个安装包没有购买代码签名证书，Windows 对所有没签名的程序都会这样提示，
   不代表有病毒。点窗口里的 **「更多信息」**，再点下面出现的 **「仍要运行」**。

3. 一路点「下一步」。默认会装到你自己的用户目录，**不需要管理员密码**。

4. 装到「正在安装运行环境」那一步会**停留 2–5 分钟**（要联网下载 Python），
   期间不要关窗口。

5. 装完双击桌面上的 **「紫鸟提现自动化」**，浏览器会自动打开管理后台，
   直接进入账台，无需创建管理员账号或输入后台登录密码。

> 紫鸟浏览器需要你**自己另外安装**，本安装包不包含它。

## 2. 配置凭据

直接打开 **「系统诊断」**，在页面的「凭据配置」区域填写：

- 紫鸟企业名称、登录账号和登录密码；
- 飞书 App ID、App Secret 和 Chat ID。

点击保存后，下一次同步或通知会直接读取新值，**不需要重启后台**。密码和 App Secret
不会回显；修改时重新输入完整值即可。

命令行仅保留为网页进不去时的维护手段：

```bat
cd /d "%LOCALAPPDATA%\ZiniaoAutomation\app"
.venv\Scripts\ziniao-automation.exe configure ziniao
.venv\Scripts\ziniao-automation.exe configure feishu
```

管理后台已移除管理员创建、登录、退出和 `configure admin` 命令。旧 `/setup`、
`/login` 书签自动跳回首页；旧管理员数据库记录仅保留兼容，不再参与访问判断。
后台仍只监听 `127.0.0.1`，拒绝远程及跨来源请求；页面自动建立本机请求校验，
无需手工配置。后台重启后，旧页面若提示校验失效，刷新即可，写入动作不会自动重放。
紫鸟账号密码、飞书 Secret 和亚马逊登录验证不受影响。

网页中的密码和 App Secret 使用隐藏输入。紫鸟密码、飞书 App Secret 存入 Windows
Credential Manager；SQLite 仅保存 `credential_ref`、App ID、Chat ID 等元数据。
命令和日志均不打印 Secret。

飞书应用需要机器人发消息权限，并将机器人加入目标群。`Chat ID` 通常以
`oc_` 开头。启用新系统前请轮换旧 App Secret。

## 3. 启动与停止

```bat
Start.bat
Stop.bat
```

浏览器打开 `http://127.0.0.1:8765`。`Start.bat` 会拒绝重复启动，
`Stop.bat` 只结束本项目记录的进程，不关闭紫鸟。

`Start.bat` 只启动本项目 D 盘虚拟环境中的
`pythonw.exe -m ziniao_automation.runner`。它不包含隐藏 PowerShell、编码命令、
下载器或自复制逻辑；后台 PID 由可审计的 Python 模块维护。早期脚本的隐藏启动命令链
容易触发安全软件误报，现已移除。

若安全软件仍保留旧记录，请确认当前文件路径和修改时间，重新扫描当前
`Start.bat`；不要恢复隔离区里的旧版本。

## 4. 登录时自动启动

双击 `Register-Startup.bat`。它注册当前 Windows 用户登录后的任务，使用当前交互桌面，
不会保存 Windows 登录密码。再次运行会安全更新任务。

## 5. 日志和清理

- JSONL 日志每日轮转，默认保留 90 天。
- 日志会递归遮盖 Password、Token、Cookie、Authorization、Secret 和 Webhook。
- 截图、报告、日志、备份可运行以下命令立即清理：

```bat
.venv\Scripts\ziniao-automation.exe cleanup --days 90
```

## 6. 小白排错

✅ **先检查**：紫鸟是否由 `Ziniao-WebDriver.bat` 启动，16851 是否监听。

✅ **需要登录验证**：点击身份检测或运行任务后，后台会调用紫鸟 `startBrowser`，自动
弹出对应店铺的可见窗口。程序会先等待紫鸟填充，再对唯一且明确的邮箱 Continue、托管
Passkey、已填密码登录和已填 6 位 OTP 执行自动点击；每个页面动作最多 3 次，每个站点
最多 3 轮，各站点分别计数。自动尝试用尽，或遇到未填内容、候选不唯一、CAPTCHA、
非托管 Passkey 等页面时，后台才显示人工继续入口。此时直接在原紫鸟窗口处理，完成后
回到本地后台点击“再次尝试自动登录并继续”；不要打开紫鸟控制台。

⚠️ **窗口未弹出或无法输入**：先在后台取消当前检测 → 退出 WebDriver 模式 → 在普通
紫鸟模式中打开对应店铺并完成登录/验证 → 关闭普通紫鸟及全部店铺窗口 → 重新运行
`D:\Vibe Seller2\Ziniao-WebDriver.bat` → 回到后台重试。普通 Chrome 只打开本地后台，
不要用它访问 Seller Central。

⚠️ **启动窗口闪退**：打开 `data\logs\ziniao-automation.jsonl`，查看最后一行的
`message`，不要复制 Cookie 或浏览器页面内容。

⚠️ **飞书不通知**：打开「系统诊断」，确认飞书凭据显示「可读取」，再点击「发送测试
消息」；同时确认机器人已进入目标群并有发消息权限。网页仍无法保存时，才使用
`configure feishu` 维护命令。

💡 **完整流程说明**：见 `README-ZINIAO.md` 和 `WORKFLOW.md`。


## 店铺账册与同步清理

- 默认只显示亚马逊店铺；名称、建档配置和任务开关可组合筛选。
- “批量建档当前筛选”只创建当前显示且需要补全的店铺队列。已有未完成队列按原清单继续，不受后续筛选影响。
- 补充站点可借用当前配置兼容的已通过站点重新读取身份，仅核验本轮选中的新站点；历史身份不直接代替实时核验。
- 单站未开通或导航超时记录后继续下一站；单家启动失败仍继续下一家。紫鸟启动最多 4 次，重试前默认等待 3/6/9 秒；通过环境变量 `ZINIAO_START_RETRY_DELAY_SECONDS` 调整基础间隔（秒，大于 0 且不超过 30，后台重启后生效）。不重启紫鸟客户端。
- 批量统计区分“本轮身份核验通过”和“本轮身份未通过”；本轮失败不会删除原有绑定。
- 完整同步成功后，当前紫鸟账号此前同步过、此次不再返回的店铺会从本地账册**实际删除**，关联排期和站点配置一并移除。手动添加、其他账号的店铺不受影响；不调用紫鸟的删除接口。
- 运行历史、资金记录、反馈记录及截图保留。独立的历史身份表不参与调度，不是隐藏的活动店铺；同一环境重新获得权限时沿用历史编号，但需要重新建档。
- 排队/待审核任务会取消。正在执行或正在建档的店铺先完成当前操作，再重新同步删除；不会在付款点击过程中强制拆除数据。
- 同步失败、列表格式异常、已知分页不完整时不删除。删除前自动创建 SQLite 一致性备份。
- 0.9.1 数据库版本仍为 0019；从 0.9.0 升级不改变表结构，从 0.8.0 升级时执行 0018–0019，启动前使用 SQLite Backup API 创建一致性备份。已删除店铺的历史不再启动或恢复执行；回到旧版时使用对应升级前备份，不直接让旧程序读取新结构。
